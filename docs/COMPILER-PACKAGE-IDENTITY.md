# Compiler package identity for Cargo-compatible dependency graphs

Research date: 2026-11-16. **Recommendation: introduce an opt-in, compiler-owned resolved package graph, package-scoped namespace identity, and per-package dependency bindings.** Keep legacy compilation unchanged until qualification. Renaming source namespaces or flattening aliases cannot provide incompatible-version coexistence. This is an implementation design, not a claim of implemented Cargo parity.

## Implementation update

Compiler fork commit [`0ce3a5ed`](https://github.com/carabistouflette/goose/commit/0ce3a5edb5679e10a490e9f66d5db5f6a30b9f63) implements the opt-in pure-Goose slice. The authoritative implemented interface and limitations are in its [graph contract](https://github.com/carabistouflette/goose/blob/0ce3a5edb5679e10a490e9f66d5db5f6a30b9f63/docs/design/package_graph.md). The remaining sections retain the original design and further acceptance goals; they are not a list of completed capabilities.

The targeted harness passes 16 tests with the normal compiler and with the compiler instrumented by Clang ASan/UBSan, including real JIT/native execution, package ownership, definition-site defaults/generics, global initialization, independent SHA-256 identity checks and malformed graphs. The broad existing suite also passes with `--nocgen` and with native Clang code generation, including 694 native code-generation checks, 860 JIT checks, 204 debug-runtime checks and 21 compiler bootstrap checks. [Validation receipt](COMPILER-VALIDATION.md). The compiler work is available as [draft PR #1](https://github.com/carabistouflette/goose/pull/1).

Current generated names add a full package fingerprint to the existing mangler; specialization numbering and internal optimizer ordering are not a stable ABI promise. Source provenance and local snapshot freshness remain producer responsibilities: the compiler does not rehash materialized source to verify the asserted graph digest. Graph-aware LSP/dumps, non-toolchain native packages, sourced-import migration, Honk graph emission and multi-version solving remain unfinished. Honk/Nest keep their existing compiler pin.

## Smallest coherent semantic model

Introduce three distinct concepts:

1. **Source identity:** immutable provenance of a source package (canonical source locator, resolved revision/checksum, package subdirectory and package name). A registry locator is an opaque canonical string to the compiler, not a Nest URL it must understand. Git means full resolved commit, not branch spelling. A path source uses a stable project-relative logical locator, with explicit source snapshot identity for reproducible builds. Absolute materialization paths remain transport information.
2. **Compilation instance identity:** source identity plus effective compilation configuration plus its sorted dependency bindings to target instance identities. The same source with different outgoing bindings can have different nominal types. Two incoming aliases pointing to the same instance do not create new instances or globals. This is deliberately separate from a package manager's release/version key.
3. **Scope identity:** `(instance handle, namespace spelling)`. Keep small integer instance handles internally, never use their load order in a published mangle or cache identity. Keep original namespace spelling for diagnostics. A typed `ScopeId`/scope record is preferable to smuggling an encoded package prefix into the old namespace string.

Replace the semantic namespace map key with `ScopeId`; store declaration scope on `SStruct`, `SEnum`, `SAlias`, `SFunction`, globals, and every reference currently carrying `ns`/`poolns`. Parser `filens`/`curns` become scopes. `NameRef` carries the resolved target scope and leaf plus qualification state. Retain human `qname` only as display data, never as a uniqueness key. Existing nominal equality through declaration identity can then distinguish versions naturally; structural primitives remain shared. Specialization keys must retain the owning declaration and nominal argument identities. Audit all name-based auxiliary caches rather than assuming `qname` is unique.

**Lookup in graph mode:** lexical locals/type parameters first; current package namespace; current package empty namespace; finally the explicitly shared compiler/stdlib scope. A library must never fall back to the application's globals or another dependency's globals. The root program has its own scope with the same local/global fallback. `::x` means this package's empty namespace; if missing, permit the explicitly shared builtin/stdlib global declaration. It does not provide an escape into the root application. Named stdlib namespaces remain shared and can be qualified unless locally shadowed. Reserve one toolchain stdlib identity; do not silently mix independently versioned stdlibs.

Preserve the existing type-kind shadowing and whole-overload-set selection rules in `LookupType`/`LookupFunctions`. UFCS looks in the receiver declaration's **package and namespace**, then the caller's existing fallback chain; never combine overloads from two versions. This follows the existing namespace mechanism, extended with an ownership dimension. Legacy mode continues to use today's single shared namespace domain, including global fallback; this behavioral difference is why opt-in is necessary. [Current lookup contract](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/ast.h#L2825-L2905).

**Dependency qualification:** add deliberate syntax in graph mode: `alias::leaf` targets that dependency's configured entry namespace; `alias::namespace::leaf` targets an explicit namespace inside it. Thus `old::Value` and `newer::Value` can both designate declarations spelled `versioned::Value` in their own sources. Within A, `dep::Value` follows A's edge; within B it follows B's edge. Keep ordinary `namespace::leaf` within the current package, and reject an alias/namespace qualifier ambiguity with a useful diagnostic instead of making resolution depend on parse order. Alias qualification is for references; declarations cannot use it to inject definitions into another package. `ParseQualifiedName` must be extended; current syntax alone does not implement this proposal. Imports still load modules; they do not globally merge dependency declarations.

**Definition scopes:** capture the complete scope on parsed references and unresolved types, not just a current checker setting. A generic body defined in A and instantiated by root still resolves `dep`, helpers, globals, defaults, UFCS and types through A. Clone paths, nested functions, constant expansion, array/index storage names, relative pools, return-from names and default expressions must preserve that scope; substituted caller expressions keep their own scope. `ParamDefaultEnv` continues to govern lexical generic bindings, while the stored scope governs package lookup. Do not “fix” this by switching a global current-package variable around calls. [Reference capture](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/parser.h#L338-L360), [default cloning](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/typecheck_calls.h#L288-L325).

## Compiler-consumable graph contract

Propose `--package-graph FILE` for `check`, `run`, `build`, and `fetch`, with a versioned JSON schema decoded through the existing JSON infrastructure. The compiler consumes resolved directories and graph edges; it neither solves versions nor contacts registry protocols in graph mode. `fetch` validates the already materialized graph and reports missing materialization; Honk owns acquisition. No graph flag means legacy behavior. Reject unsupported schema versions/unknown semantic fields rather than partially applying them.

Illustrative schema (node labels are file-local references, **not ABI IDs**; fingerprints are computed by the compiler):

```json
{
  "schema": "goose-package-graph-v1",
  "compiler_revision": "<exact qualified compiler commit>",
  "root": "app",
  "nodes": [
    {"key":"app", "source":{"locator":"workspace:app", "revision":"snapshot:<digest>", "name":"app", "subdir":""}, "directory":".", "entry":"app.goose", "entry_namespace":"", "bindings":{"a":"A", "b":"B"}, "config":{}},
    {"key":"A", "source":{"locator":"registry:example/A", "revision":"sha256:<archive-digest-A>", "name":"A", "subdir":""}, "directory":"vendor/A", "entry":"A.goose", "entry_namespace":"A", "bindings":{"dep":"dep1"}, "config":{}},
    {"key":"B", "source":{"locator":"registry:example/B", "revision":"sha256:<archive-digest-B>", "name":"B", "subdir":""}, "directory":"vendor/B", "entry":"B.goose", "entry_namespace":"B", "bindings":{"dep":"dep2"}, "config":{}},
    {"key":"dep1", "source":{"locator":"registry:example/dep", "revision":"sha256:<archive-digest-1>", "name":"dep", "subdir":""}, "directory":"vendor/dep-1", "entry":"dep.goose", "entry_namespace":"versioned", "bindings":{}, "config":{}},
    {"key":"dep2", "source":{"locator":"registry:example/dep", "revision":"sha256:<archive-digest-2>", "name":"dep", "subdir":""}, "directory":"vendor/dep-2", "entry":"dep.goose", "entry_namespace":"versioned", "bindings":{}, "config":{}}
  ]
}
```

Paths are relative to the graph file, canonicalized for I/O and checked against package boundaries. The CLI root source must match the root node entry. `entry` and sidecar stem come from package metadata, never from an incoming alias: alias `old` may load `dep.goose` and `dep.build`. `entry_namespace` makes the shorthand explicit and must identify that entry's declared namespace (empty is valid). Explicit namespace-qualified access works for other namespaces in the package. Compiler validation must not infer identity from display version, alias, directory basename or source file renaming.

Prevalidate duplicate keys/aliases, missing edges, invalid identifiers, entry escapes, identity/configuration conflicts, cycles, resource limits, and compiler contract compatibility before parsing source. JSON decoding must detect duplicate object keys. Only an empty `config` is supported in v1; future feature/target settings require a schema/capability extension. Reject unknown feature requests now. Package cycles are rejected initially; ordinary within-package module cycles retain legacy handling. Distinguish a bounded resource error from an invalid graph. Preserve node/edge provenance for import diagnostics.

For bare imports, consult the importing instance's binding table rather than the root table; local module versus dependency ambiguity stays an error. Relative imports stay inside their owning package. Stdlib fallback is explicit and shared; graph mode must not accidentally invoke blessed fetching when a dependency binding is missing. Sourced imports inside libraries become assertions against that library's edge, or an actionable missing-binding error. Never overwrite edges from source. A path assertion checks materialized source ownership; a Git assertion must be attested by the graph producer's resolved provenance. Unresolved tag/range assertions must fail pending a defined attestation contract, rather than inherit today's ref-mismatch warning. Honk must normalize or attest legacy sourced imports before graph emission.

### Stable IDs, source deduplication and initialization

Specify a domain-separated, length-delimited canonical byte encoding (not ad hoc JSON concatenation). Instance fingerprint = full SHA-256 of source tuple, entry/entry namespace, supported effective config, and bytewise alias-sorted outgoing bindings to target fingerprints. Compute bottom-up on the validated DAG; graph labels, incoming aliases, node order and physical directory paths do not contribute. Source revisions must be immutable. For local development, derive the snapshot digest from a specified sorted source/sidecar input manifest (excluding generated outputs and the graph itself) and refresh it on edits; this is build freshness, not a claim that a mutable directory is immutable. Producer verifies registry/archive provenance; compiler validates graph consistency, and cache freshness still covers actual compilation inputs.

Use the full digest and retain canonical identity records for equality: if a digest is ever reused for unequal records, reject clearly. Do not truncate to `Hex8`, sanitize refs as identity, hash only aliases, or use `std::hash`. This requires a reviewed deterministic SHA-256 implementation or existing vetted utility identified during implementation; the inspected cache helpers alone are insufficient. Set generous explicit graph/identity length limits to bound hostile inputs.

Key parsed compilation units by `(instance identity, normalized package-relative source path)`. A physical text buffer may be shared by canonical filesystem path, but AST nodes, file indices, `filepkg`, import provenance and initialization rank belong to an instance. Two aliases of one instance parse its source once and initialize its globals once. The same physical file in two different instances is parsed twice. Reject duplicate materializations claiming one immutable identity with conflicting contents; do not let “first file loaded” choose semantics. Include context in `loaded`, `fileof`, `importedat`, failure tracking and the post-order initialization graph, not only in the queue. Preserve imported-before-importer global initialization with deterministic traversal; document cycle ordering rather than promise topological ordering for module cycles. [Current worklist/ranking](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/main.cpp#L252-L455).

Generated graph-mode C names start with a reserved package fingerprint prefix and an injective length-delimited/hex encoding of namespace and declaration name. Function specialization suffixes encode the declaration signature, nominal type arguments and any specialization-affecting constant/context values; do not expose `FnSpec::id` as stable ABI. Anonymous internal temporaries may retain local counters because they are not identity or ABI. Route structs/enums, enum tag prefixes, globals, specialized functions and helper names through one naming helper; retain `SameMangle` checks as assertions/defense. Identity-bearing names must not depend on `Unique` or `_m1` collision order. Preserve legacy naming and explicit header/extern/export C names by default.

This guarantees package separation, not full byte-identical generated C: existing optimizer traversal and internal temporary numbering need separate reproducibility qualification. Definition-site source offsets for anonymous entities, if needed, must use package-relative paths and stable spans, not absolute paths or load indices.

## Native boundaries: isolate generated symbols, constrain foreign symbols

A renamed generated Goose function can coexist with its other version. Two static archives exporting the same third-party C symbol generally cannot. Distinct native build directories and `dlopen` handles also do not prove ELF/PE/Mach-O symbol isolation or prevent TinyCC's raw-name registration from selecting the wrong address. Preserve the existing C header/extern ABI in legacy mode. Graph mode must not silently rename explicit `extern` C symbols or C exports; that would break external code. [JIT registration](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/jit.h#L69-L78), [symbol tables](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/native.h#L167-L194).

First implementation: reject graph-mode non-stdlib native sidecars, explicit foreign externs/dylibs and exported C ABI surfaces before native build or JIT loading. Permit only the existing toolchain-owned runtime/stdlib ABI through an explicit trusted path. This conservative gate allows a useful pure-Goose multi-version milestone without pretending native parity. Legacy native package behavior remains available without graph mode.

Following native patch: add compiler metadata analogous to Cargo's `links`: one logical native library provider per final process/link unit. The same provider instance reached by multiple aliases is legal; two distinct instances claiming the same link identity error with both dependency chains. Carry the link identity through sidecar/graph metadata and cache stamps. Honk's solver must enforce the same constraint before download/build, and the compiler must independently validate it. [Cargo links constraint](https://doc.rust-lang.org/cargo/reference/resolver.html#links).

Also collect explicit C symbol ownership and ABI declarations before TinyCC registration/linking; reject conflicting providers and incompatible repeated declarations. Compatible repeated declarations of one provider need not error. Include builtin symbol providers and explicit export names in this check. A `links` declaration alone cannot detect undeclared symbols in third-party archives; require accurate metadata and qualify object-symbol inspection where available. Initially reject unqualified combinations instead of relying on platform symbol interposition. Dynamic-library names/spellings need package ownership too, even when raw ABI remains unchanged.

Native cache keys in graph mode must include full instance fingerprint, compiler/runtime ABI revision, C toolchain identity, target/profile/options, header ABI and actual native input digests. Keep directories and stamps separated from legacy caches; verify stored full keys. Package-specific generated ABI headers must key any native consumer rebuild. An opt-in future native symbol-prefix contract could support cooperative libraries; automatic rewriting of arbitrary third-party objects is outside this minimal design.

## Dumps, diagnostics, LSP and compatibility

Do not let two `versioned::Value` declarations collapse in a dump. A future graph dump needs a versioned context preamble plus package blocks with original namespace declarations, sources and dependency edges, and a package-aware reparse path. A single flat renamed namespace is insufficient because definition-site dependency bindings must survive. Preserve the self-contained declaration-dump promise; a machine-specific external graph path alone is not a roundtrip. Test parse/dump/parse and recompilation behavior, including generics and default scopes. Until this format exists, reject graph-mode AST/declaration dump and roundtrip options clearly, before producing lossy output. Legacy dump tests stay unchanged. [Baseline dump roundtrip](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/main.cpp#L489-L523).

Diagnostics should print readable `package@revision [short display fingerprint]::namespace::name` where ambiguity matters, plus physical file/line and both dependency chains. Short fingerprints are display only; retain full machine IDs in structured diagnostics. Alias spelling belongs to the use site, not the declaration identity. Wrong-version type errors must show both origins even when the source type names match. Preserve location ranges and existing JSON output shape through optional additive context fields.

LSP must analyze the same graph as CLI compilation, supplied in initialization/configuration per entry program, with graph-file changes invalidating analysis. Scope-aware lookup and actual declaration pointers support go-to-definition, references, rename, hover and completions; never select a declaration by `qname` alone. One URI may participate in two instances: edits update shared text, but queries need entry/instance context. Where that is ambiguous, return multiple contextual results or require an active root instead of silently selecting the first analysis. Include package identity in index/cache keys and preserve dependency import navigation. Until supported, explicitly reject graph configuration in LSP rather than reporting a legacy flat analysis as valid. [Current workspace selection](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/lsp_workspace.h#L367-L383).

Expose graph schema/capability and compiler source revision in machine-readable toolchain reporting. The first producer should require an exact qualified compiler pin; this is safer than assuming a runtime version hash proves graph ABI compatibility. Later relax only to an explicitly versioned compatibility contract. Honk should emit the graph atomically beside lock/output data, pass it for every compiler invocation including checks/tests/builds, and fail early with an upgrade hint for an older compiler. Keep legacy emission until the new pin and graph capability are selected. Nest's archive compiler-pin policy needs a deliberate migration; adding this file does not change it. [CLI/report entry points](https://github.com/carabistouflette/goose/blob/eadca409f68210893f366e60d0c2f0dc29a339be/src/main.cpp#L1352-L1488), [audit/pin policy](https://github.com/carabistouflette/goose-nest/blob/8348788/docs/CARGO-PARITY.md).

## Alternatives and decision

| Alternative | Assessment |
| --- | --- |
| Rewrite namespaces/source per selected version | Small apparent diff, but modifies source semantics, diagnostics and dumps; fails definition-context bindings and native ABI isolation. Reject. |
| Flat alias-to-path dictionary | Useful legacy acquisition adapter; cannot represent A's `dep` and B's `dep` independently, or distinguish multiple aliases from multiple compilation instances. Reject as the semantic interface. |
| Separate compiler process/C translation unit per package | Can isolate some generated C, but generics, whole-program optimization, type exchange and native ABI require a larger separate-compilation contract. Defer. |
| Opaque package-prefixed namespace strings everywhere | Could reduce signature churn, but conflates source spelling, scope and ABI; dump and alias parsing remain difficult. Prefer a typed scope key. |
| Scoped graph + current whole-program compiler | Adds an ownership dimension at existing lookup seams, retains nominal declaration pointers and existing optimizer. Recommended; broad reference-context audit is unavoidable. |

## Staged implementation and qualification

### Patch 1: opt-in pure-Goose package identity

## First implementation brief for the parent

Implement the pure-Goose graph slice on the already prepared compiler branch at `eadca409f68210893f366e60d0c2f0dc29a339be`. Start with validated instance records and a typed scope key, then update parser/reference ownership and `ParseProgram` together. Make A and B's same-spelled `dep` edges resolve independently before adding syntactic alias convenience. Finish definition-site lookup and deterministic generated naming in that slice; reject unsupported native/tooling surfaces explicitly. Add the bounded harness and obtain positive two-version JIT/AOT plus wrong-version nominal rejection, generic/default-scope and global-sharing receipts. Preserve legacy tests and ABI. Only then qualify a new compiler pin and enable Honk graph emission/multi-version solving. Do not repin consumers based solely on a passing namespace-collision probe.

Specific risks/unknowns to resolve during implementation:

- Scope is carried in more places than declaration names: pool/index/return/expansion nodes and parser rollback can leak cross-instance bindings if missed. The compiler build plus targeted adversarial fixtures must drive a complete audit.
- Existing specialization identity includes contextual state beyond plain type arguments; canonicalizing every identity-bearing generated function name without encoding transient frame IDs needs careful inspection of `GetOrCreateSpec` and its keys. Keep unnamed private temporaries out of the ABI promise.
- The smallest safe stdlib sharing boundary needs tests for stdlib generics that accept user nominal types and namespace shadowing. Do not infer that all blessed/native packages can be shared like the runtime.
- Canonical local-source snapshots and sourced Git/tag assertions need an agreed producer contract; absolute paths or mutable branch names are not a reproducibility solution. Exact archive provenance remains the producer's responsibility, separate from compiler unit-cache freshness.
- Native metadata cannot prove the absence of undeclared third-party symbols; qualification must distinguish declared link conflicts, symbol-table conflicts, and platform loader behavior. Keep rejection gates until supported combinations are demonstrated.
- A lossless dump requires package context, not just longer qualified names. LSP's one-URI/multiple-instance selection also needs a deliberate user-visible context policy.
- The proposed SHA-256/canonical encoding and graph schema are new implementation work; measure limits, hashing overhead and cache reuse. No load-order counters, truncated identity hashes or silent digest-collision aliasing are acceptable shortcuts.
